# Мост пробуждения PC MATE

## Зачем он нужен

Выключенный компьютер не принимает команды из интернета: агент не работает,
сеть почти обесточена. Жива только сетевая карта, и она слушает единственную
вещь — «магический пакет» Wake-on-LAN. Этот пакет — широковещательная
UDP-датаграмма, и маршрутизаторы её наружу не пускают.

Значит, отправить пакет может только устройство **внутри вашей домашней сети**.
Когда вы дома — это телефон. Когда вас нет — нужен кто-то, кто всегда включён.
Это и есть мост: он держит соединение с сервером PC MATE и по команде будит
компьютер.

```
Телефон (мобильный интернет) → Сервер → Мост (дома) → UDP 9 → Компьютер
```

---

## Что выбрать

| | ESP32 | Raspberry Pi / Linux |
|---|---|---|
| Цена | ~500 ₽ | если уже есть — бесплатно |
| Потребление | ~0,5 Вт | 2–5 Вт |
| Настройка | точка доступа с телефона | один скрипт |
| Когда брать | специально ради моста | дома уже крутится Pi, NAS или домашний сервер |

Годится и любой другой всегда включённый компьютер с Linux — хоть роутер с
OpenWrt и Python.

## ESP32

```bash
cd bridge/esp32
pio run -t upload        # прошить
pio device monitor       # смотреть журнал (115200)
```

При первом запуске плата поднимет точку доступа **«PC MATE Bridge»**
(пароль `pcmate123`). Подключитесь к ней телефоном — откроется страница
настройки, где нужно указать:

* домашнюю сеть Wi-Fi и пароль;
* адрес сервера, например `wss://relay.example.com`;
* идентификатор компьютера (в приложении: **Ещё → Диагностика**);
* секрет регистрации, если вы его задали на сервере.

Дальше плата сама зарегистрируется, привяжется к компьютеру и начнёт ждать
команды. Воткните её в любую зарядку 5 В.

**Светодиод:** горит ровно — связь с сервером есть; мигает — связи нет.

**Сбросить настройки:** зажать BOOT и перезагрузить плату.

Поддерживаются `esp32dev` и `esp32-c3` (см. `platformio.ini`).

## Raspberry Pi / Linux

```bash
cd bridge/linux
sudo ./install.sh wss://relay.example.com <идентификатор-компьютера>
```

Скрипт поставит зависимости, создаст пользователя `pcmate`, положит файлы в
`/opt/pcmate`, настройки — в `/etc/pcmate/bridge.json` и запустит службу.

```bash
systemctl status pcmate-bridge
journalctl -u pcmate-bridge -f
```

Проверить отправку пакета вручную:

```bash
python3 /opt/pcmate/pcmate_bridge.py --test-wol AA:BB:CC:DD:EE:FF
```

## Настройки моста

`/etc/pcmate/bridge.json` (или NVS на ESP32):

| Поле | Значение |
|---|---|
| `relay_url` | адрес сервера, `wss://relay.example.com` |
| `pc_id` | идентификатор компьютера из приложения |
| `device_id` | идентификатор моста (создаётся сам) |
| `device_token` | токен сервера (получается при регистрации) |
| `broadcast` | широковещательный адрес вручную, если автоопределение ошибается |
| `registration_secret` | если на сервере задан `PCMATE_REGISTRATION_SECRET` |

---

## Что мост знает и чего не знает

Мост **не участвует в сквозном шифровании**. Он получает только служебное
сообщение `wol.request` с MAC-адресом и отвечает, удалось ли отправить пакет.

Команды «выключить», сценарии и расписания проходят мимо него в зашифрованном
виде — ключей у моста нет и быть не может.

Худшее, что может сделать скомпрометированный мост, — включить ваш компьютер.

---

## Требования к сети

* Мост и компьютер должны быть **в одной подсети**. Через VLAN, гостевую сеть
  или второй роутер магический пакет не пройдёт.
* Мосту нужен только исходящий доступ в интернет — порты пробрасывать не нужно.
* Если в роутере включена «изоляция клиентов» (AP Isolation), выключите её.
