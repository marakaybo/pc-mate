## Совместимость трёх реализаций

Криптография написана трижды: C# (BouncyCastle + `AesGcm`), TypeScript
(`@noble/*`) и эталон на `node:crypto`. Все три сверяются с общими тестовыми
векторами [`docs/test-vectors.json`](test-vectors.json):

* X25519 — публичные ключи и общий секрет совпадают (проверено и с известным
  вектором RFC 7748);
* HKDF-SHA256 — оба направленных ключа совпадают побайтно;
* AES-256-GCM — шифротекст при одинаковом nonce совпадает побайтно;
* отпечатки пары и ключа совпадают;
* подмена маршрутных полей ломает проверку подлинности — на обеих сторонах;
* магический пакет совпадает побайтно.

Если кто-то тронет криптографию, CI-задача `vectors` это заметит.

| Синхронизация версии во всех компонентах одной командой | `tools/set-version.mjs` |
| Создание ключа подписи Android и подготовка секретов | `tools/make-keystore.ps1` |
| Проверка обновлений раз в сутки в приложении и в агенте | `mobile/src/lib/updates.ts`, `Session/UpdateChecker.cs` |

Выпуск версии — три команды:

```bash
node tools/set-version.mjs 1.1.0
git commit -am "Версия 1.1.0"
git tag v1.1.0 && git push --follow-tags
```

Подробности и чек-лист — в [release.md](release.md).

**Репозиторий и ключ подписи готовы:**

* код опубликован: <https://github.com/marakaybo/pc-mate> (публичный);
* CI проходит: агент, сервер, приложение, мост и сверка векторов протокола;
* ключ подписи Android создан (RSA 4096, до 2056 года), секреты в репозитории
  заданы — APK будет подписан автоматически;
* обе программы проверяют обновления на `marakaybo/pc-mate`.

**Резервная копия ключа — на вас.** Файл `%USERPROFILE%\.pcmate\pcmate-release.jks`
и пароль рядом с ним: перенесите пароль в менеджер паролей, а ключ — на второй
носитель. Потеря означает, что обновлять приложение будет нельзя.

**Выпуск v1.0.0 намеренно не создан:** сначала проверьте программу на живом
железе (см. ниже), иначе в публичный релиз уйдут непроверенные файлы.

## Что нужно проверить руками

Это невозможно проверить без живого окружения — нужен ваш компьютер, телефон,
роутер и сервер.

### Обязательно

1. **Установка.** Запустить `agent/install.ps1` от администратора (или собрать
   установщик Inno Setup) и убедиться, что служба стартует, а в трее появился значок.
2. **Сопряжение.** Собрать приложение (`cd mobile && npx expo run:android`),
   отсканировать QR и сверить отпечатки на обоих экранах.
3. **Тест таймера пробуждения.** Мастер → «Тест таймера пробуждения». Критерий
   приёмки из ТЗ — 5 успехов из 5.
4. **Тест Wake-on-LAN из домашнего Wi-Fi.** Мастер → «Тест Wake-on-LAN», затем
   кнопка «Включить» в приложении. Тоже 5 из 5.
5. **Выключение с телефона.** Убедиться, что на ПК появляется окно отсчёта и
   что кнопка «Отмена» действительно отменяет.
6. **Сценарий.** Создать «Вечер» из списка программ и проверить, что отчёт
   приходит на телефон.

### Если нужен удалённый доступ

7. Развернуть сервер (`docker compose up -d`), вписать адрес в настройках агента.
8. Собрать мост (ESP32 или Raspberry Pi) и проверить включение из мобильного
   интернета — 5 из 5.

## Что я не стал решать за вас

| Вопрос | Почему |
|---|---|
| Домен и VPS для сервера | Нужны ваши учётные записи и оплата |
| Резервная копия ключа подписи | Ключ создан, но хранить его копию должны вы: утечёт или потеряется — обновлять приложение станет нельзя |
| Публикация выпуска v1.0.0 | Файлы соберутся по тегу, но выкладывать в публичный доступ непроверенные на железе сборки — ваше решение |
| Сертификат подписи кода для установщика | Стоит около 15 000 ₽ в год и выдаётся на конкретное лицо. Без него SmartScreen предупреждает при первом запуске; поддержка подписи в workflow уже есть |
| Проект FCM или RuStore Push | Нужны ваши ключи; сервер уже принимает токены (`POST /push/register`), осталось вписать отправку |
| `projectId` в `app.json` | Заполняется при первом `eas build` под вашей учётной записью — сейчас там заглушка. Для сборки APK через GitHub Actions он не нужен |
| Включать ли автовход Windows | Влияет на безопасность вашей машины; мастер показывает состояние и объясняет последствия, но сам не включает и пароль не запрашивает |

## Известные ограничения

| Что | Подробности |
|---|---|
| Wake-on-LAN с телефона не работает в Expo Go | Нужен нативный модуль `react-native-udp`: `npx expo run:android` или сборка EAS. Всё остальное в Expo Go работает |
| Виджеты и ярлыки на рабочем столе телефона | Требуют нативного кода (`AppWidgetProvider`, `ShortcutManager`) — в чистом JS не делаются |
| Иконки программ в списке | Агент отдаёт PNG в base64, приложение пока показывает только название и путь |
| Отправка push | Сервер хранит токены, но не отправляет уведомления: нужно выбрать FCM или RuStore |
| iOS | Код кроссплатформенный, но на устройстве не проверялся — нужен Mac |
| `setInsecure()` в прошивке ESP32 | Микроконтроллер не проверяет сертификат сервера. Риск ограничен: мост умеет только включать компьютер. Для строгих требований вшейте отпечаток сертификата |
| Мастер на разных материнских платах | Логика опирается на стандартные API Windows, но поведение BIOS у производителей разное — проверяйте тестовым пробуждением |

```bash

cd agent  && dotnet build PcMate.sln && dotnet test
cd server && npm install && npm test && npm run typecheck
cd mobile && npm install && npm test && npm run typecheck

# Проверить готовность компьютера без установки службы
agent/src/PcMate.Agent.Service/bin/Debug/net8.0-windows10.0.19041.0/PcMate.Agent.Service.exe --check

# То же с автоматическим исправлением (нужна консоль администратора)
... --check --fix

# Пересчитать векторы протокола после изменений в криптографии
node tools/gen-test-vectors.mjs
```

Главные точки входа при доработке:

| Задача | Где смотреть |
|---|---|
| Новая команда протокола | `docs/protocol.md` → `PcMate.Core/Protocol/Names.cs` → `CommandDispatcher` → `mobile/src/lib/protocol.ts` |
| Новый тип шага сценария | `PcMate.Core/Models/Scenario.cs` → `StepExecutor` (трей) или `ScenarioEngine` (служба) → `ScenarioEditorScreen` |
| Новая проверка в мастере | `CheckIds` → `ReadinessChecker.RunSingleAsync` → `TitleOf` |
| Новый экран приложения | `mobile/src/navigation.tsx` |
