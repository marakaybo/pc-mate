# Выпуск версии

PC MATE раздаётся через **GitHub Releases**, а не через магазины приложений.
Значит, две вещи мы берём на себя сами: подпись файлов и уведомление
пользователей об обновлениях. Обе уже настроены — ниже что и как работает.

---

## Как выпустить версию

```bash
# 1. Проставить версию во все компоненты сразу
node tools/set-version.mjs 1.1.0

# 2. Проверить, что всё собирается
cd agent  && dotnet test && cd ..
cd server && npm test && cd ..
cd mobile && npm test && cd ..

# 3. Зафиксировать и поставить тег
git commit -am "Версия 1.1.0"
git tag v1.1.0
git push --follow-tags
```

Дальше GitHub Actions сделает всё сам: соберёт установщик Windows и APK,
подпишет их, посчитает контрольные суммы и создаст выпуск с готовыми файлами.

Следить за ходом: вкладка **Actions** → workflow **Release**.

---

## Что попадает в выпуск

| Файл | Что это |
|---|---|
| `PcMate-Setup-1.1.0.exe` | Установщик для Windows 10/11 (~10 МБ) |
| `PcMate-1.1.0.apk` | Приложение для Android 8+ |
| `*.sha256` | Контрольные суммы |

Установщик сам ставит службу, правило брандмауэра, включает гибернацию и
таймеры пробуждения, а при отсутствии **.NET 8 Desktop Runtime** скачивает его
с сайта Microsoft. От пользователя не требуется ничего искать вручную.

## Подготовка (один раз)

### 1. Ключ подписи Android

Без магазина подписывать APK нужно самим. Ключ создаётся один раз и живёт
вечно: Android разрешает обновлять приложение **только тем же ключом**.

```powershell
./tools/make-keystore.ps1
```

Скрипт создаст `pcmate-release.jks`, покажет отпечаток и подготовит base64 для
секрета. Дальше: **Settings → Secrets and variables → Actions → New secret**:

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | содержимое `pcmate-release.jks.base64.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `pcmate` |
| `ANDROID_KEY_PASSWORD` | пароль ключа |

> **Сделайте резервную копию файла ключа.** Потеряете — придётся выпускать
> приложение с новым идентификатором, а пользователям удалять старое и ставить
> заново, теряя настройки.

Если секретов нет, сборка не упадёт: APK будет подписан отладочным ключом и
получит имя `PcMate-1.1.0-debug-signed.apk`. Ставить его можно, **но обновить
на подписанную версию потом не выйдет** — только переустановкой.

### 2. Репозиторий для проверки обновлений

В `mobile/app.json` есть заглушка:

```json
"extra": { "github": { "owner": "ВАШ_ЛОГИН", "repo": "pcmate" } }
```

Для сборок в CI это подставляется автоматически из `github.repository`.
Для локальных сборок впишите свой логин руками.

То же самое для агента — в `UpdateChecker.cs`:

```csharp
public const string Owner = "pcmate";
public const string Repo = "pcmate";
```

### 3. Сертификат подписи кода Windows (по желанию)

Без подписи Windows SmartScreen при первом запуске покажет
«Windows защитила ваш компьютер». Это не ошибка и не вирус — так помечается
любая программа от издателя без сертификата. Пользователь нажимает
«Подробнее» → «Выполнить в любом случае».

Если сертификат есть, добавьте секреты — установщик подпишется сам:

| Секрет | Значение |
|---|---|
| `WINDOWS_CERT_BASE64` | PFX-сертификат в base64 |
| `WINDOWS_CERT_PASSWORD` | пароль к нему |

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard
```

Сертификат для подписи кода (OV) стоит примерно 15 000 ₽ в год, EV — дороже,
но снимает предупреждение SmartScreen сразу, без накопления репутации.

## Как обновляются пользователи

Магазина нет, поэтому обе программы проверяют обновления сами:

* **Приложение** — раз в сутки спрашивает GitHub про последний выпуск. Если
  вышел новее, показывает карточку на главном экране и в разделе «Ещё» со
  ссылкой на APK. Версию можно пропустить — тогда о ней больше не напомнят.
* **Агент** — тот же механизм, раз в сутки; предлагает скачать установщик.
  Есть и ручная проверка: трей → «Проверить обновления».

Установка поверх сохраняет настройки, сопряжения, сценарии и расписания:
они лежат в `C:\ProgramData\PcMate`, а установщик их не трогает.

## Сборка вручную

Если нужно собрать всё локально, без GitHub Actions.

### Установщик Windows

```powershell
cd agent
./build.ps1 -Version 1.1.0
# → agent/dist/PcMate-Setup-1.1.0.exe + .sha256
```

Нужен **Inno Setup 6**. Если нет прав администратора — портативная установка:

```powershell
# скачайте innosetup-6.7.3.exe с https://jrsoftware.org/isdl.php
.\innosetup-6.7.3.exe /VERYSILENT /PORTABLE=1 /DIR="$env:LOCALAPPDATA\Programs\InnoSetup6"
```

`build.ps1` найдёт его там сам.

Вариант без зависимости от .NET на целевом компьютере (установщик ~60 МБ):

```powershell
./build.ps1 -Version 1.1.0 -SelfContained
```

### APK

```bash
cd mobile
npm install
npx expo prebuild --platform android
cd android && ./gradlew assembleRelease
```

APK окажется в `android/app/build/outputs/apk/release/`. По умолчанию он
подписан отладочным ключом — для раздачи подпишите своим:

```bash
BUILD_TOOLS=$ANDROID_HOME/build-tools/34.0.0
$BUILD_TOOLS/zipalign -f -p 4 app-release.apk aligned.apk
$BUILD_TOOLS/apksigner sign --ks ~/.pcmate/pcmate-release.jks \
  --ks-key-alias pcmate --out PcMate-1.1.0.apk aligned.apk
$BUILD_TOOLS/apksigner verify --print-certs PcMate-1.1.0.apk
```

## Проверка перед публикацией

- [ ] `node tools/set-version.mjs X.Y.Z` — версия одинаковая везде
- [ ] Тесты агента, сервера и приложения проходят
- [ ] Установщик ставится на чистой машине без .NET
- [ ] Обновление поверх предыдущей версии сохраняет сопряжения и сценарии
- [ ] APK ставится поверх предыдущего (значит, ключ тот же)
- [ ] Приложение видит новую версию в карточке обновления
- [ ] Заметки к выпуску описывают, что изменилось

## Если что-то пошло не так

**Сборка Android падает на `expo prebuild`** — проверьте, что в `app.json`
заполнено `android.package` и что версии плагинов совпадают с версией Expo
(`npx expo install --check`).

**APK не ставится поверх старого** — подписан другим ключом. Это ключевая
причина хранить `pcmate-release.jks` как зеницу ока.

**Установщик ругается «Не удалось скачать .NET»** — на компьютере нет
интернета. Соберите вариант `-SelfContained`: он несёт рантайм в себе.

**Выпуск создался пустым** — посмотрите артефакты задач `windows` и `android`
во вкладке Actions: файлы собираются там и копируются в выпуск задачей `publish`.
