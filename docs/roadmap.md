## Что осталось и почему

### Требует живого железа

Эти вещи невозможно проверить в среде разработки — нужен настоящий компьютер,
телефон и роутер:

1. Пробуждение по таймеру из гибернации (5 из 5 попыток).
2. Пробуждение магическим пакетом из домашнего Wi-Fi (5 из 5).
3. Пробуждение через мост из мобильного интернета (5 из 5).
4. Поведение мастера готовности на разных материнских платах.
5. Сборка APK и установка на телефон.

### Требует решения владельца

| Вопрос | Почему нельзя решить за вас |
|---|---|
| Домен и VPS для сервера | Нужны ваши учётные записи и оплата |
| Ключ подписи Android-приложения | Секрет, который должен родиться у вас |
| Подпись установщика Windows | Нужен сертификат разработчика (~15 000 ₽/год) |
| Публикация в RuStore / Google Play | Учётные записи разработчика |
| Проект FCM или RuStore Push | Учётная запись и файл `google-services.json` |

### Технический долг

* **Виджеты Android** — нужен нативный модуль (`AppWidgetProvider`) и
  Expo config plugin; в чистом JS не делается.
* **Ярлыки на рабочем столе телефона** — то же самое (`ShortcutManager`).
* **Отправка push** — сервер хранит токены, но не отправляет: нужно выбрать
  FCM или RuStore и вписать ключи.
* **Иконки программ в списке** — агент отдаёт PNG в base64, приложение их пока
  не рисует (показывает только название и путь).
* **iOS** — код готов, но не проверялся на устройстве; нужен Mac для сборки.

## Идеи на будущее

* Наблюдение за температурой и загрузкой в реальном времени (график в приложении).
* Запуск сценария по геозоне: «когда я в 2 км от дома — включить компьютер».
* Несколько компьютеров в одном сценарии (рабочий + домашний).
* Экспорт и импорт сценариев файлом.
* Поддержка Linux-агента (systemd + `rtcwake` вместо Планировщика).
* Голосовое управление через «Алису» или Google Assistant — сервер уже умеет
  принимать команды по HTTP.
