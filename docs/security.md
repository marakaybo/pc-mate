# Безопасность PC MATE

Программа управляет питанием компьютера и запускает на нём программы. Значит,
цена ошибки — чужой доступ к вашей машине. Ниже — от чего защищаемся, как и
что осознанно оставлено на усмотрение пользователя.

---

## 1. Модель угроз

| # | Угроза | Ответ |
|---|---|---|
| 1 | Сервер-ретранслятор скомпрометирован или принадлежит недоверенному лицу | Сквозное шифрование: сервер видит только `from`, `to`, `ts` и размер. Содержимое команд ему недоступно |
| 2 | Трафик перехвачен в Wi-Fi или у провайдера | TLS снаружи + AEAD внутри. Даже без TLS содержимое остаётся закрытым |
| 3 | Перехваченную команду «выключить» повторяют через час | Временная метка (±120 с) и одноразовый nonce в скользящем окне 600 с |
| 4 | Сервер пытается переслать команду не тому компьютеру | Маршрутные поля входят в AAD — подмена ломает тег аутентификации |
| 5 | Чужой сканирует QR-код или подсматривает его | Токен одноразовый и живёт 5 минут; после сопряжения гасится |
| 6 | Посредник подменяет ключ при сопряжении | Отпечаток пары показывается и на ПК, и на телефоне — пользователь их сверяет |
| 7 | Сканирование портов домашней сети | На ПК нет входящих портов для интернета; локальный порт 8760 открыт только для частных сетей и требует сопряжения |
| 8 | Украден телефон | Ключи в Keystore/Keychain, привязаны к устройству; отзыв доступа с компьютера мгновенный |
| 9 | Украден или скопирован файл ключей с ПК | Ключ зашифрован DPAPI в области LocalMachine с дополнительной энтропией — на другой машине не расшифруется |
| 10 | Сценарий используют для выполнения произвольного кода | Шаг «выполнить команду» выключен по умолчанию и включается только на самом компьютере |
| 11 | Подбор токена устройства на сервере | Токен — 32 случайных байта; в базе только SHA-256; сравнение с постоянным временем; ограничение частоты запросов |
| 12 | Чужое устройство регистрируется на вашем сервере | Необязательный общий секрет регистрации и возможность закрыть регистрацию после настройки |

## 2. Криптография

### Сопряжение

```
телефон: (privPhone, pubPhone) — X25519, живут постоянно
ПК:      (privPc, pubPc)       — X25519, живут постоянно

shared = X25519(privPhone, pubPc) = X25519(privPc, pubPhone)
prk    = HKDF-Extract(SHA-256, salt = pairId, ikm = shared)

kPhone→Pc = HKDF-Expand(prk, "pcmate/v1/phone->pc", 32)
kPc→Phone = HKDF-Expand(prk, "pcmate/v1/pc->phone", 32)
```

`pairId` — уникальный идентификатор пары, поэтому повторное сопряжение тех же
двух устройств даёт **новые** ключи.

Общий секрет из одних нулей (ключ малого порядка) отвергается на обеих сторонах.

### Сообщения

AES-256-GCM, nonce 12 случайных байт, тег 16 байт.

```
AAD = utf8("v|id|from|to|ts")
```

AAD связывает шифротекст с маршрутом. Сервер не может ни подменить получателя,
ни «состарить» сообщение — тег перестанет сходиться.

### Защита от повтора

Получатель отвергает сообщение, если:

* расхождение времени больше 120 секунд, **или**
* nonce уже встречался за последние 600 секунд, **или**
* тег AEAD не сошёлся.

### Отпечаток

```
fp = SHA-256("pcmate-fp/v1" || min(pubA,pubB) || max(pubA,pubB))
```

Первые 15 байт → 6 групп по 4 символа Crockford-Base32 (без похожих символов
I, L, O, U). Одинаковая строка на ПК и телефоне означает, что посредника нет.

## 3. Хранение секретов

| Секрет | Где | Как защищён |
|---|---|---|
| Приватный ключ ПК | `%ProgramData%\PcMate\identity.json` | DPAPI, область LocalMachine, доп. энтропия `PcMate/v1/agent-identity` |
| Токен ПК для сервера | `%ProgramData%\PcMate\server.json` | то же |
| Приватный ключ телефона | Android Keystore / iOS Keychain | `expo-secure-store`, доступ только при разблокированном устройстве |
| Токен телефона для сервера | там же | отдельный ключ на каждый сервер |
| Токены устройств на сервере | SQLite | хранится только SHA-256; сравнение с постоянным временем |
| Ключи сессий | оперативная память | выводятся заново при каждом запуске из приватного ключа и публичного ключа собеседника |

Сессионные ключи **нигде не сохраняются**: их всегда можно вывести заново, а
значит, нечего и красть.

## 4. Разграничение прав

**Что телефон может:** питание, сценарии, расписания, мастер готовности, статус,
история, отзыв собственного доступа.

**Что телефон не может:**

* создать новый код сопряжения (только с самого ПК) — иначе один сопряжённый
  телефон мог бы втихую пригласить второй;
* включить выполнение произвольных команд;
* включить автовход Windows.

Эти три вещи меняются только физически на компьютере.

---

## 5. Сетевая поверхность

| Точка | Порт | Кому доступна |
|---|---|---|
| Агент → сервер | исходящее 443 | — |
| Локальный сервер агента | входящий TCP 8760 | правило брандмауэра `profile=private,domain`; требуется сопряжение |
| Wake-on-LAN | входящий UDP 9 | принимает сетевая карта, не операционная система |
| Сервер-ретранслятор | 443 (Caddy) | интернет; за TLS |

**На домашнем роутере не нужно открывать ни одного порта.** Все соединения
исходящие.

## 6. Осознанные компромиссы

**Автовход Windows.** Чтобы сценарии работали после включения из полностью
выключенного состояния (S5), нужен вход в систему. PC MATE **не хранит и не
запрашивает пароль Windows**: мастер лишь показывает состояние автовхода и
объясняет, как включить его вручную через `netplwiz`, с предупреждением, что
любой человек с физическим доступом попадёт в вашу учётную запись. По умолчанию
выключено. Рекомендуемый путь — гибернация: сеанс сохраняется, автовход не нужен.

**Выполнение произвольных команд.** Шаг `command` — законный способ сделать в
сценарии что угодно, и он же — самый опасный. Поэтому: выключен по умолчанию,
включается только в настройках агента на самом ПК, с подтверждением, и телефон
переключить его не может.

**Мост пробуждения и сквозное шифрование.** Мост не участвует в шифровании
команд: он получает только служебное `wol.request` с MAC-адресом. Худшее, что
может сделать скомпрометированный мост, — включить компьютер. Читать команды он
не способен: у него нет ключей.

**`setInsecure()` в прошивке ESP32.** Микроконтроллер не хранит корневые
сертификаты и не имеет часов на момент первого подключения. Это ослабляет
проверку сертификата сервера на этапе регистрации. Риск ограничен: единственное,
что мост передаёт, — запрос на отправку магического пакета. Для повышенных
требований в прошивку можно вшить отпечаток сертификата вашего сервера.

## 7. Журналирование

Агент пишет журнал в `%ProgramData%\PcMate\logs` (7 дней). В журнал попадают
имена команд и результаты — **но не содержимое сценариев, не ключи и не токены**.

Сервер пишет структурированный JSON; поля с именами `token`, `secret`,
`password`, `pub`, `cipher` обрезаются до неузнаваемости.

## 8. Что делать при компрометации

1. **Потерян телефон** → на компьютере: трей → Настройки → выбрать телефон →
   «Отозвать доступ». Ключи этого телефона становятся бесполезны немедленно.
2. **Скомпрометирован сервер** → замените адрес сервера в настройках агента.
   Прочитать прошлые команды злоумышленник не сможет — у него нет ключей.
   Локальный режим продолжает работать.
3. **Скомпрометирован компьютер** → удалите `%ProgramData%\PcMate` и
   переустановите агента: будет создана новая идентичность, все сопряжения
   аннулируются.

## 9. Проверка реализации

Тесты, относящиеся к безопасности:

* `CryptoTests` — согласование ключей, направленность, AEAD, отпечатки;
* `ReplayGuardTests` — повторы, расхождение часов, отсутствующий nonce;
* `InteropTests` — совпадение с эталонными векторами, поломка при подмене AAD;
* `test/crypto.test.ts` (мобильное приложение) — то же со стороны телефона;
* `test/database.test.ts` (сервер) — токены, захват чужого идентификатора, пары;
* `test/api.test.ts` (сервер) — доступ к чужим расписаниям и событиям.

```bash
cd agent  && dotnet test
cd server && npm test
cd mobile && npm test
```
