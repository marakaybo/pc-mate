# Решение проблем

Собрано по принципу «симптом → причина → что сделать». Начните с мастера
готовности: он закрывает большинство случаев сам.

---

## Компьютер не просыпается по команде с телефона

### 1. Убедитесь, что телефон в домашнем Wi-Fi

Магический пакет не проходит через интернет. Если телефон на мобильных данных,
включение возможно **только через мост пробуждения**.

Приложение так и напишет: «Телефон не в домашней сети».

### 2. Проверьте пункты мастера

| Пункт | Что делать |
|---|---|
| «Сетевая карта может будить компьютер» — ✕ | Нажмите «Исправить» |
| «Пробуждение по магическому пакету» — ✕ | Нажмите «Исправить» |
| «Подключение по кабелю» — ! | Подключите Ethernet. Wake-on-WLAN на большинстве ПК не работает |
| «Wake-on-LAN в BIOS» — ? | См. ниже |

### 3. Включите Wake-on-LAN в BIOS/UEFI

Это самая частая причина. Программно проверить нельзя — только включить.

1. Перезагрузите компьютер, нажмите Del или F2 при включении.
2. Найдите пункт: **Wake on LAN**, **Power on by PCI-E/PCI**, **Resume by LAN**,
   **Power on by Onboard LAN** — у разных плат разные названия. Обычно в разделе
   Power Management / APM / Advanced.
3. Включите.
4. Найдите **ErP Ready** или **Deep Sleep** — если есть, **выключите**: они
   обесточивают сетевую карту в выключенном состоянии.
5. Сохраните (F10) и загрузитесь в Windows.
6. Повторите «Тест Wake-on-LAN» в мастере.

### 4. Проверьте, из какого состояния не просыпается

| Состояние | Что значит |
|---|---|
| Из сна (S3) просыпается, из выключения (S5) нет | Нормально для многих плат. Пользуйтесь гибернацией |
| Из гибернации (S4) не просыпается | Отключите «Быстрый запуск» (мастер умеет) и проверьте ErP в BIOS |
| Не просыпается ни из какого | Почти наверняка BIOS или драйвер сетевой карты |

### 5. Обновите драйвер сетевой карты

Драйвер Microsoft «по умолчанию» часто не поддерживает пробуждение. Скачайте
драйвер с сайта производителя материнской платы (Realtek, Intel) и установите.

## Компьютер не просыпается по расписанию

Расписание «включить» не использует сеть — только таймер Windows.

1. Мастер → «Таймеры пробуждения разрешены» должен быть ✓. Если нет — «Исправить».
2. Откройте **Планировщик заданий** → папка **PC MATE**. Задача должна быть там,
   в её свойствах на вкладке «Условия» — галочка «Пробуждать компьютер для
   выполнения задачи».
3. **Для ноутбуков:** на батарее задачи по умолчанию не выполняются. Включите в
   настройках агента «Разрешить таймеры пробуждения при работе от батареи».
4. Проверьте, не выключен ли компьютер полностью: таймер работает из сна и
   гибернации, но **не из состояния S5**.
5. Выполните «Тест таймера пробуждения» в мастере.

Проверить, что именно разбудило компьютер:

```powershell
powercfg /lastwake
```

Посмотреть, кому вообще разрешено будить компьютер:

```powershell
powercfg /devicequery wake_armed
```

## Телефон не видит компьютер в домашней сети

1. **Брандмауэр.** Правило должно существовать:
   ```powershell
   netsh advfirewall firewall show rule name="PC MATE (локальная сеть)"
   ```
   Если правила нет:
   ```powershell
   netsh advfirewall firewall add rule name="PC MATE (локальная сеть)" dir=in action=allow protocol=TCP localport=8760 profile=private,domain
   ```

2. **Тип сети.** Windows должна считать сеть **частной**, а не общедоступной:
   Параметры → Сеть и Интернет → свойства подключения → «Частная сеть».

3. **IP компьютера изменился.** Мастер это заметит («IP-адрес изменился»).
   Закрепите адрес в роутере: DHCP → Резервирование адресов → MAC компьютера.

4. **Изоляция клиентов в роутере.** Некоторые роутеры запрещают устройствам в
   Wi-Fi видеть друг друга (AP Isolation / Client Isolation) — выключите.

5. Проверьте вручную с телефона в браузере: `http://<ip-компьютера>:8760/health`.
   Должен ответить JSON с именем компьютера.

## Нет связи через сервер

1. Проверьте сервер:
   ```bash
   curl https://relay.ваш-домен.ru/api/v1/health
   ```
   Ожидается `{"ok":true,...}`.

2. Посмотрите журнал агента: `C:\ProgramData\PcMate\logs\agent-<дата>.log` —
   строки «Нет связи с сервером».

3. Проверьте адрес в настройках агента: должен быть вида
   `wss://relay.ваш-домен.ru` (не `http://`, не с путём `/ws` в конце — агент
   допишет сам).

4. Сертификат: Caddy получает его автоматически, но только если домен
   действительно указывает на сервер. Проверьте A-запись.

5. Журнал сервера: `docker compose logs -f relay`.

## Сценарий не запускает программы

**«Нет активного сеанса пользователя»** — никто не вошёл в Windows. Служба
работает в Session 0 и не может открывать окна.

* После **гибернации** сеанс сохраняется — сценарии работают.
* После **полного выключения** нужен вход в систему. Либо входите вручную, либо
  включите автовход (`netplwiz`, снять галочку «Требовать ввод имени пользователя
  и пароля»), понимая, что это снижает безопасность.

**Значок PC MATE пропал из трея** — помощник закрыт. Запустите
`C:\Program Files\PC MATE\PcMate.Tray.exe` или перезайдите в Windows.

**Шаг «Выполнить команду» не работает** — он выключен по умолчанию. Включается
только на компьютере: трей → Настройки → «Разрешить шаг „Выполнить команду“».

## Служба не запускается

```powershell
Get-Service PcMateAgent
Start-Service PcMateAgent
Get-Content "C:\ProgramData\PcMate\logs\agent-$(Get-Date -Format yyyy-MM-dd).log" -Tail 50
```

Если в журнале «Не удалось занять порт 8760» — порт занят другой программой.
Смените его в настройках агента.

Полная переустановка службы:

```powershell
sc.exe stop PcMateAgent
sc.exe delete PcMateAgent
cd "путь\к\agent"
./install.ps1 -SkipBuild
```

## Мост пробуждения не отвечает

**ESP32:**

* светодиод **горит ровно** — связь с сервером есть;
* **мигает** — связи нет;
* журнал: `pio device monitor` (115200 бод);
* сбросить настройки: зажать BOOT при включении — поднимется портал настройки.

**Raspberry Pi / Linux:**

```bash
systemctl status pcmate-bridge
journalctl -u pcmate-bridge -f

# проверить отправку пакета вручную
python3 /opt/pcmate/pcmate_bridge.py --test-wol AA:BB:CC:DD:EE:FF
```

Мост должен быть **в той же подсети**, что и компьютер. Через VLAN или
гостевую сеть магический пакет не пройдёт.

## Приложение: «Модуль отправки UDP недоступен»

Wake-on-LAN с телефона требует нативного модуля, которого нет в Expo Go.
Соберите обычное приложение:

```bash
cd mobile
npx expo run:android      # или eas build -p android --profile preview
```

Все остальные функции (выключение, сон, сценарии, расписания) работают и в Expo Go.

## Полезные команды Windows

```powershell
# Какие состояния сна доступны и что их блокирует
powercfg /a

# Что разбудило компьютер в прошлый раз
powercfg /lastwake

# Кому разрешено будить компьютер
powercfg /devicequery wake_armed

# Кто может быть разбужен, но сейчас не настроен
powercfg /devicequery wake_programmable

# Разрешить конкретному устройству будить компьютер
powercfg /deviceenablewake "Realtek PCIe GbE Family Controller"

# Включить гибернацию
powercfg /hibernate on

# Настройки пробуждения сетевой карты
Get-NetAdapterPowerManagement -Name "Ethernet"
Get-NetAdapterAdvancedProperty -Name "Ethernet" -RegistryKeyword "*WakeOnMagicPacket"

# Задачи PC MATE в Планировщике
schtasks /Query /TN "\PC MATE\" /FO LIST /V
```
